# p967-c5-usb — приём DAP по границам USB-передач (ESP32-S3)

Ветка `feat/s3-usb-packets` от `origin/feat/s3-idf61` (5f7663f). PR не открыт.

## Что сделано
- `main/dap_pktring.{h,c}` — чистое кольцо пакетов (один производитель — задача TinyUSB, один потребитель — задача DAP,
  C11-атомики, без FreeRTOS). Одна USB-передача = один элемент ≤ 64 байт; переполнение и пакет > 64 — пакет отбрасывается
  и считается (`dap_pktring_overflow`), принятые и их порядок не трогаются.
- `tests/host/test_pktring.c` + `tests/host/run.sh` — хост-тест (`sh tests/host/run.sh`). Сначала коммит с тестом и заглушкой
  «поток байт» (как прежнее `tud_vendor_read`): **RED: 63** (склейка двух коротких запросов и всё, что за ней). Затем кольцо: **GREEN**.
  Случаи: два коротких запроса не склеиваются; порядок и оборот индексов; переполнение (новый теряется, старые целы, место
  освобождается); пакет ровно 64 и 65 байт; пустая передача (ZLP).
- `main/usb_dap.c`: `tud_vendor_rx_cb(buffer, bufsize)` кладёт пакет в кольцо и будит задачу DAP (ядро 1, как было);
  задача берёт по одному и отвечает строго по порядку.
- `sdkconfig.defaults.esp32s3`: `CONFIG_TINYUSB_VENDOR_RX_BUFSIZE=0`. `DAP_PACKET_COUNT` для S3: 1 → **8**.

## Отступления от задания (проверено по исходникам TinyUSB в managed_components)
1. **Очередь — не `xQueue`, а своё кольцо.** Чистое кольцо и есть очередь на DAP_PACKET_COUNT пакетов по 64 байта; дублировать
   его FreeRTOS-очередью незачем (иначе чистая часть не покрывала бы то, что едет в плату). Пробуждение — `xTaskNotifyGive`, как прежде.
2. **При RX_BUFSIZE=0 TinyUSB уходит в небуферизованный режим и для TX** (`CFG_TUD_VENDOR_TXRX_BUFFERED = RX>0 && TX>0`).
   В нём нет `tud_vendor_read_flush`/`tud_vendor_write_flush` (не компилируются) — убраны. Приём перевооружается сам после возврата
   из коллбэка; `tud_vendor_write` шлёт ≤ 64 байт одной передачей и возвращает 0, пока прежний ответ в пути (цикл с `vTaskDelay(1)`
   остаётся; ответ DAP ≤ 64 байт — в одну передачу). Буфер коллбэка живёт только внутри него — копируем.

## Проверка
- `sh tests/host/run.sh` → GREEN.
- `idf.py set-target esp32s3 && idf.py build` (IDF v6.1) → rc=0; `usb_dap.c` и `dap_pktring.c` собраны.
- В чистом клоне подмодуль `components/corsacOTA` пуст — сборка требует `git submodule update --init components/corsacOTA` (к правке не относится).

## Не проверено (железо — лид)
- Прогон OpenOCD/pyOCD на стенде с `DAP_PACKET_COUNT=8`: исчезновение «CMSIS-DAP command mismatch», выигрыш по скорости.
- Счётчик переполнений на стенде в лог не выводится (доступен `dap_pktring_overflow`) — при желании добавить в `monitor.c`.
- Риск: запросы приходят из коллбэка TinyUSB-задачи, ответы пишутся из задачи DAP (другое ядро) — `usbd_edpt_claim` берёт мьютекс
  TinyUSB; на стенде смотреть, нет ли зависаний при потоке коротких запросов.
